## Deployment Patterns

### Blue-Green Deployment
- Maintain two identical environments
- Switch traffic atomically via DNS or load balancer
- Instant rollback capability

### Canary Deployment
- Route percentage of traffic to new version
- Monitor error rates and latency
- Gradually increase traffic or rollback

### Rolling Update
- Update instances incrementally
- Maintain minimum available replicas
- Kubernetes default strategy

### GitOps
- Git as single source of truth for infrastructure
- Automated reconciliation (ArgoCD, Flux)
- Pull-based deployment model

## ✅ Post-Deployment Verification (MANDATORY)

After ANY deployment or infrastructure mutation, run a read-only check that confirms the new state. **Never declare a deployment successful based solely on a zero exit code.**

### Verification Mapping

| Operation | Verify with | Expected state |
|---|---|---|
| k8s rollout | `kubectl rollout status deployment/<name>` + `kubectl get pods -l app=<name>` | rollout complete, all pods Ready |
| blue-green switch | `curl -sf https://<new-env>/health` | HTTP 2xx before cutting traffic |
| canary | error rate + p99 latency of the canary subset (Prometheus / CloudWatch) | within defined thresholds before scaling up |
| IaC apply (Terraform) | `terraform plan` post-apply | no diff (zero changes) |
| IaC apply (CloudFormation) | `aws cloudformation describe-stacks --stack-name <name>` | StackStatus=CREATE_COMPLETE or UPDATE_COMPLETE |
| container deploy | `docker ps --filter name=<name>` + container healthcheck | status=healthy |
| systemd service | `systemctl is-active <service>` | active (running) |

### Behavior on Mismatch

1. Report the mismatch: expected vs. actual state.
2. **Rollback immediately** if a rollback path exists (blue-green: switch traffic back; k8s: `kubectl rollout undo`; Terraform: `terraform apply` of the previous state file).
3. Enter the `docs/TROUBLESHOOTING.md` Layer 1–4 diagnostic protocol.
4. Never declare the deployment successful on a mismatch.

## Best Practices

1. **Version Everything**: Infrastructure code, configs, and scripts must be versioned in git
2. **Idempotent Operations**: All scripts and automation must be safe to run multiple times
3. **Secrets Management**: Never hardcode — use Vault, AWS Secrets Manager, OCI Vault, or environment variables via CI/CD
4. **Environment Parity**: Dev, test, and prod should differ only in scale, never in architecture
5. **Backup Before Changes**: Always snapshot/backup before infrastructure modifications
6. **Document Runbooks**: Every operational procedure should have a runbook
7. **Capacity Planning**: Monitor trends, not just thresholds — predict before you react
8. **Cost Optimization**: Right-size resources, use spot/preemptible instances, implement auto-scaling
