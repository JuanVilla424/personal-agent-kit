# Temp Directory Structure - BMAD

**Version**: 1.0.1
**Last Updated**: 2025-11-02

---

## 📋 Overview

The `temp/` directory is the **working area** for BMAD session management, context persistence, and project planning. It's organized to clearly distinguish between **active work** and **completed items**.

**Purpose**:

- Session continuity (auto-continue system)
- Project planning and proposals
- Validation reports
- Context snapshots for recovery

---

## 📁 Directory Structure

```
temp/
├── plans/                    # Active planning documents
│   ├── improvement-proposal.md    # Current proposal (ALWAYS update, NEVER version)
│   └── completed/            # Archived completed proposals
│       └── improvement-proposal-YYYYMMDD.md
│
├── reports/                  # Validation and compliance reports
│   └── version-compliance-report.md
│
├── snapshots/                # Context snapshots (auto-generated)
│   └── context-snapshot-YYYYMMDD-HHMMSS.md
│
├── archive/                  # Old files safe to delete
│   └── [old files moved here by cleanup scripts]
│
├── bmad-state.json          # Current session state (DO NOT DELETE)
├── current-context.md       # Human-readable context (DO NOT DELETE)
├── user-messages-history.md # User message log (DO NOT DELETE)
│
└── [trigger files]          # Auto-generated by hooks (temporary)
    ├── session-start-trigger.md
    ├── continue-trigger.md
    └── token-check-trigger.txt
```

## 📂 Directory Details

### `temp/plans/` - Active Planning

**Purpose**: Current, active planning documents

**Rules**:

- ✅ **ALWAYS update existing files** (e.g., `improvement-proposal.md`)
- ❌ **NEVER create versioned files** (no `-v2`, `-v3`, etc.)
- ✅ Use descriptive filenames without versions
- ✅ Move to `completed/` when work is done

**Example Workflow**:

```bash
# Create new proposal
Write temp/plans/improvement-proposal.md

# Update it later (CORRECT)
Edit temp/plans/improvement-proposal.md

# Move when completed
mv temp/plans/improvement-proposal.md temp/plans/completed/improvement-proposal-20251102.md

# Create next proposal with same name
Write temp/plans/improvement-proposal.md
```

**Common Files**:

- `improvement-proposal.md` - Project improvement proposals
- `feature-plan.md` - Feature planning documents
- `refactor-plan.md` - Refactoring plans

---

### `temp/plans/completed/` - Completed Plans

**Purpose**: Archive of completed proposals and plans

**Rules**:

- ✅ Files moved here are TIMESTAMPED (YYYYMMDD format)
- ✅ Safe to delete after 30+ days
- ✅ Kept for historical reference
- ✅ Never modified after moving here

**Naming Convention**:

```
[original-name]-YYYYMMDD.md
```

**Examples**:

- `improvement-proposal-20251102.md`
- `feature-plan-authentication-20251025.md`

---

### `temp/reports/` - Validation Reports

**Purpose**: Compliance, validation, and analysis reports

**Rules**:

- ✅ Update reports in place (don't version)
- ✅ Keep recent reports (last 30 days)
- ✅ Archive old reports to `archive/`

**Common Files**:

- `version-compliance-report.md` - Protocol version validation
- `test-results.md` - Test execution reports
- `security-audit.md` - Security scan results

---

### `temp/snapshots/` - Context Snapshots

**Purpose**: Automatic context backups for session recovery

**Generated By**:

- `autocompact` skill (when token usage high)
- Manual context saves

**Rules**:

- ✅ AUTO-GENERATED - do not edit manually
- ✅ Kept for 7 days by cleanup script
- ✅ Timestamped: `context-snapshot-YYYYMMDD-HHMMSS.md`
- ✅ Used for disaster recovery

**Cleanup Policy**:

```bash
# Automated by .claude/scripts/cleanup-temp.sh
# Keeps only snapshots from last 7 days
find temp/snapshots/ -name "*.md" -mtime +7 -delete
```

---

### `temp/archive/` - Safe to Delete

**Purpose**: Long-term storage for old files before deletion

**Rules**:

- ✅ Files older than 30 days moved here automatically
- ✅ **Safe to delete manually** anytime
- ✅ Cleaned automatically by cleanup script
- ✅ No critical files stored here

**What Goes Here**:

- Old snapshots (>30 days)
- Obsolete proposals
- Deprecated reports
- Temporary test files

---

## 🔒 Critical Files (NEVER DELETE)

These files are essential for BMAD operation:

### `temp/bmad-state.json`

**Purpose**: Current session state for auto-continue

**Contains**:

- Active agent name
- Current task description
- Project phase
- Last updated timestamp

**Used By**: Auto-continue system, session-start hook

---

### `temp/current-context.md`

**Purpose**: Human-readable current context

**Contains**:

- Current work summary
- Recent decisions
- Pending tasks
- Important notes

**Used By**: Auto-continue, context recovery, manual reference

---

### `temp/user-messages-history.md`

**Purpose**: Log of recent user messages

**Contains**:

- Chronological message history
- User preferences
- Important instructions

**Used By**: Context recovery, preference tracking

---

## 🧹 Cleanup Policy

### Automated Cleanup

Script: `.claude/scripts/cleanup-temp.sh`

**What Gets Cleaned**:

```bash
# Snapshots older than 7 days
temp/snapshots/*-*.md (mtime > 7 days)

# Archive older than 30 days
temp/archive/* (mtime > 30 days)

# Trigger files older than 1 day
temp/*-trigger.* (mtime > 1 day)
```

**What NEVER Gets Cleaned**:

- `temp/bmad-state.json`
- `temp/current-context.md`
- `temp/user-messages-history.md`
- `temp/plans/` (active files)
- `temp/reports/` (recent reports)

---

## 🚫 Anti-Patterns (DON'T DO THIS)

### ❌ Creating Versioned Files

```bash
# WRONG
temp/plans/improvement-proposal-v2.md
temp/plans/feature-plan-v3.md
temp/reports/compliance-report-version-2.md

# CORRECT
temp/plans/improvement-proposal.md  # Update this file
mv temp/plans/improvement-proposal.md temp/plans/completed/improvement-proposal-20251102.md
temp/plans/improvement-proposal.md  # Create fresh
```

**Validation**: `.claude/scripts/validate-no-versioning.sh` blocks `-v2`, `-v3` files

---

### ❌ Deleting Critical Files

```bash
# NEVER DO THIS
rm temp/bmad-state.json
rm temp/current-context.md
rm temp/user-messages-history.md
```

---

### ❌ Manual Snapshot Editing

```bash
# DON'T EDIT SNAPSHOTS
Edit temp/snapshots/context-snapshot-20251102-142500.md

# They are READ-ONLY historical records
```

## 📊 Workflow Examples

### Example 1: Creating and Completing a Proposal

```bash
# 1. Create new proposal
Write temp/plans/improvement-proposal.md

# 2. User reviews and requests changes
Edit temp/plans/improvement-proposal.md  # Update in place

# 3. User approves
# Complete the work...

# 4. Move to completed
mv temp/plans/improvement-proposal.md \
   temp/plans/completed/improvement-proposal-20251102.md

# 5. Ready for next proposal (same name)
```

---

### Example 2: Recovering from Context Loss

```bash
# 1. Session restarted, context lost
# User says: "continue"

# 2. Auto-continue hook reads:
Read temp/bmad-state.json          # Last agent and task
Read temp/current-context.md       # Human context
Read temp/snapshots/[latest].md    # Full snapshot if needed

# 3. Session restored successfully
```

---

### Example 3: Manual Cleanup

```bash
# Check what can be safely deleted
ls -lh temp/archive/
ls -lh temp/snapshots/

# Clean old archives (optional - script does this)
rm temp/archive/*

# Clean old snapshots (keep recent ones)
find temp/snapshots/ -name "*.md" -mtime +7 -delete
```

## 🔧 Integration with Auto-Continue

The `temp/` structure is tightly integrated with the auto-continue system:

1. **Session Start**:
   - Hook reads `bmad-state.json` and `current-context.md`
   - Loads project context from this structure

2. **During Work**:
   - State updated in `bmad-state.json` after each task
   - Context updated in `current-context.md` periodically

3. **On "Continue"**:
   - Hook detects keyword
   - Reads temp/ files to restore exact state

4. **On Compact**:
   - `autocompact` skill saves snapshot to `temp/snapshots/`
   - Updates `current-context.md` with critical info
